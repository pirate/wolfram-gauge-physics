# Exact engine × gauge product evolution

The product layer attaches a finite-fiber connection to every raw state and immutable event emitted
by the pinned `HypergraphRewritingEngine`. It exists because quotienting the base hypergraph before
attaching connection data is not generally sound: a connection can break an automorphism that made
two bare-base matches equivalent.

## State and event semantics

A raw product state is

`(engine raw hypergraph state, fiber template, connection)`.

Its physical identity quotients both arbitrary base-vertex relabelings and independent local fiber
frames. The exact implementation first finds the least bare-base adjacency code, retains every
labeling tied for that code, and only then minimizes the gauge-fixed connection signature. This
factorization is lexicographically equivalent to the original all-labelings definition and is
exhaustively differential-tested over every connection on every unlabeled base graph through four
vertices for a two-element gauge group.

The supported engine event morphology is currently strict:

`{x,y} -> {x,w},{w,y}`,

with one consumed simple binary edge, two produced simple binary edges, and exactly one fresh
vertex. The product layer reconstructs this morphism from the engine event's actual consumed and
produced edge IDs; it does not guess from state differences. It factors the old transport through
the new fiber with the fresh frame fixed to identity, verifies the induced base equals the engine's
raw output state, and fails closed on every other morphology.

Every product event records the raw and physical state IDs, subdivision vertices, gauge-orbit size,
amplitude `1/sqrt(|Aut(F)|)` per labeled factorization, and whether the exact curvature sector
changed. The orbit norm is checked as

`|Aut(F)| * |amplitude|^2 = 1`.

This is a local gauge-orbit isometry. No global amplitude over distinct spatial rewrite matches is
assigned because that would require a dynamical law not yet derived.

## Causality

The product layer imports the causal edges generated by the actual engine events and automatically
attaches before/after connection sectors to every event. The transport-preserving subdivision rule
therefore provides a zero-change control: any reported curvature change is a correctness failure,
not an interesting physical signal.

At depth two on a triangle, the engine produces 16 raw states, 15 events, and six causal edges. For
a `C4` fiber these collapse to three physical product states while preserving a nontrivial initial
holonomy sector on every event.

## Why the engine runs unquotiented

The product runner requires `StateCanonicalizationMode::None` and full raw-state exploration. A
bare-base quotient does not know which graph automorphisms preserve the attached connection, so
using its reduced transition set could omit physically distinct product transitions. The current
raw run is the exact reference semantics.

The eventual high-performance integration should add fiber-template and connection labels to the
engine's canonical state itself. Only then can quotient exploration safely happen before raw
provenance is expanded.

## Dynamics boundary

The runner can apply an exact unary holonomy map after subdivision, but the complete `D4` census
shows that every reversible, flatness-preserving, inversion- and conjugation-equivariant unary map
fixes all physical conjugacy sectors. Apparent changes of based holonomy are gauge-representative
motion, not curvature propagation. See `causal-dynamics.md`.

The implemented two-cell Hurwitz exchange escapes this no-go by coupling adjacent cells while
remaining reversible and gauge-covariant. It is not yet attached to engine events: doing so
correctly now builds on `evolve_cell_product`, which threads first-class `OrientedCellComplex` face
boundaries through every raw spatial event. What remains is a distinct gauge-event type whose
causal dependencies are derived from its explicit face/link read and write sets.

## Measured scaling

On the recorded M1 Max run, depth four produced 436 raw states, 435 events, and 336 causal edges but
only five physical product states. The median complete runtime over three repetitions was 0.852 s.
The optimized exact canonicalizer evaluates expensive gauge signatures only on canonical
base-labeling ties; the original definition is retained in the tests as a differential oracle.

Reproduce the measurement with:

```bash
python3 bench/product_evolution_scaling.py --repetitions 3 --max-steps 4
```

The raw result is in `bench/results/m1-max-product-scaling.json`. Timing is machine-specific; state,
event, causal-edge, and curvature counts are deterministic.
